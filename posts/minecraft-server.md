事情是从一句"你能不能开个服务器大家一起玩"开始的。

听起来很简单。真正动手才发现，我家的网络条件几乎是最难的那一档：没有公网 IPv4，躲在运营商的 CGNAT 后面，中间还隔了一层随身 WiFi。按常规做法，这事在第一步就死了。

最后它跑起来了，异地朋友也能进。下面是完整过程，以及几个把我卡了挺久的坑。

## 先说结论：卡在哪

我在动手前先摸了一遍自己的网络，这一步非常值得，因为它直接决定了后面能走哪条路：

```text
本机 IPv4        192.168.1.23       ← 私有地址，外面访问不到
出口公网 IPv4    39.xxx.xxx.xx      ← 运营商的共享地址
公网 IPv6        2409:xxxx:xxxx::/64  ← 真的有
```

三个关键判断：

- **出口 IPv4 不是你独占的。** `39.144` 开头是中国移动的数据网段，这个地址在运营商那一层被很多用户共享。你在路由器里怎么设端口映射都没用，因为流量根本到不了你家。
- **你还不止一层 NAT。** `172.20.10.x` 这个网段通常出现在随身 WiFi 或手机热点后面，也就是说运营商 NAT 之外，路由器自己又是一层。
- **但你有真正的公网 IPv6。** 这是唯一的"天然通路"，后面会用到。

所以"端口映射"这条路从一开始就不存在。不用去路由器后台折腾了。

## 服务端选型

| 项目 | 选择 | 为什么 |
|---|---|---|
| 服务端核心 | Purpur | Paper 的下游分支，插件生态完全兼容，但多了不少可调项 |
| 版本 | 26.2 | 见下面那个坑 |
| 运行环境 | Java 25 | 硬性要求，不是建议 |

Purpur 的好处是它和 Paper 完全兼容，所以社区里的插件和教程基本都能直接套用。坏处是……没什么坏处。

## 坑一：版本和插件会互相打架

我一开始用的是最新版 26.3，服务端起得来，但基岩版互通插件 Geyser 直接报错：

```text
Couldn't find asBukkitCopy or asCraftMirror method on CraftItemStack
```

查下来是上游的事：Paper 在 26.3 里移除了 `CraftItemStack#asCraftMirror`，而 Geyser 内嵌的命令解析库还在找这个方法。这不是配置问题，等插件更新才能解决。

Geyser 官方文档写得很明确，它当时只支持到 **26.2**。所以我退了一个小版本，问题消失。

**教训**：选版本的时候，先去看你要用的插件支持到哪，再决定服务端版本。反过来做就是白折腾。

## 坑二：Java 版本是硬门槛

26.x 的服务端要求 **Java 25**，低于这个版本连启动都启动不了，报错很直接：

```text
Minecraft 26.1 and newer requires running the server with Java 25 or above.
```

我机器上原本是 Java 21。这里建议**别动系统里的 Java**，直接下一个便携版解压到项目目录里，用启动脚本指定路径。这样不会影响其他任何依赖 Java 的软件。

## 坑三：虚空世界不是设个参数就行

空岛玩法的第一步是"没有地面"。我用的是超平坦生成器加虚空生物群系：

```properties
level-type=minecraft:flat
generator-settings={"layers":[{"block":"minecraft:air","height":1}],"biome":"minecraft:the_void"}
generate-structures=false
```

世界确实是空的了。但紧接着有两个反直觉的问题：

**第一，出生点选在了半空。** 原版的出生点选择逻辑是找一个"能站人的地方"，在一个全是空气的世界里它选出来的位置很可能是悬空的。玩家一进来就开始下坠。

**第二，`fill` 和 `setblock` 在未加载的区块上会失败。** 我本来想用一个数据包自动生成初始小岛，结果命令全部报 `That position is not loaded`。因为虚空世界里那些区块默认根本没被加载。

解决办法是先强制加载，再建造：

```mcfunction
forceload add -16 -16 16 16
```

这一行必须放在建造命令之前。另外出生点附近要用 `respawn_radius` 设成 0，否则玩家会在出生点周围随机落点，很容易直接掉进虚空。

> 顺带一提，26.x 把游戏规则的命名整体改成了下划线风格。`spawnRadius` 现在是 `respawn_radius`，`doDaylightCycle` 是 `advance_time`。老教程里的名字全部失效，这个坑我踩了。

## 让异地朋友连进来

这是最开始的问题。既然端口映射走不通，可选的其实就三条路，我都实测过：

| 方案 | 可行性 | 说明 |
|---|---|---|
| 端口映射 | 不行 | 没有公网 IPv4，物理上做不到 |
| IPv6 直连 | 可行但有条件 | 你已经有公网 IPv6，但对方也必须有 |
| 内网穿透 | 最稳 | 客户端主动向外连，不挑网络环境 |

**IPv6 直连**的好处是免费、延迟最低，缺点是那个地址会变。移动分配的前缀是动态的，网络重连之后就会刷新，所以每次都要重新把地址发给朋友。而且校园网、公司网经常没有 IPv6，对方不一定能连。

**内网穿透**是把你的服务主动连到一台有公网 IP 的中转服务器上，外网流量从那条隧道转进来。它不需要你有公网 IP、不用改路由器、对方也不需要 IPv6。代价是速度受中转服务器限制。

我最后两条路都留着了：平时用 IPv6 直连，需要发给不确定网络环境的朋友时用内网穿透。

> 关于延迟：我实测到中转节点是 64ms，而我到公共 DNS 的基线是 54ms。也就是说这个中转只多花了 10ms 左右，比我一开始担心的要好得多。经验判断在实测数据面前经常是错的。

## 最后让它变成一个像样的地址

隧道会给你一个 `节点域名:五位数端口` 这样的地址，难记、难发。我在前面加了一层 DNS 的 **SRV 记录**，把它变成了：

```text
mc.你的域名
```

玩家只输域名，端口藏在 DNS 里。这部分值得单独写一篇，见《为什么别人的服务器地址不用带端口》。

## 复盘

回头看，整件事的难点根本不在 Minecraft，而在网络。真正花时间的是三件事：

1. **搞清楚自己的网络到底能做什么。** 这一步花十分钟，能省掉后面几小时的无效尝试。
2. **先查插件支持到哪个版本，再定服务端版本。**
3. **别相信"应该可以"，去实测。** 我担心的跨运营商延迟是 10ms，我没想到的 Java 版本是硬门槛。

服务器现在跑着。世界是一片虚空加一座巴掌大的小岛，一棵树，一个箱子。挺荒凉的，但从零开始造东西的乐趣就在这里。
