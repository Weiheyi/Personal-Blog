你在游戏里添加服务器的时候，可能注意过一件事：有些服务器的地址特别短。

```text
mc.hypixel.net
```

没有端口。而你自己搭的服务器的地址长这样：

```text
play.example.com:25577
```

后面那个五位数字很丑，也很难发给别人。加个 SRV 记录就能去掉它。

## 原理

Minecraft 客户端内置了一套查询逻辑：当玩家输入的地址**不带端口**时，客户端会先去 DNS 里查一条特定名字的记录：

```text
_minecraft._tcp.<玩家输入的地址>
```

如果这条记录存在，它里面就写着"真正该连哪台主机、哪个端口"。客户端照着连，玩家完全不需要知道端口是多少。

这条记录就是 **SRV 记录**（RFC 2782 定义的标准 DNS 记录类型）。它本来是为了让服务发现自动化设计的，Minecraft 只是它的一个使用场景。

举个具体例子。假设你的服务在 `relay.example.com` 的 `34567` 端口上：

```text
_minecraft._tcp.play.example.com.  SRV  0 5 34567 relay.example.com.
```

翻译过来就是："玩家查 `play.example.com` 时，连 `relay.example.com` 的 34567 端口。"

那条记录里四个数字的含义：

| 字段 | 值 | 含义 |
|---|---|---|
| 优先级 Priority | 0 | 数字越小越优先，多台服务器时用来排序 |
| 权重 Weight | 5 | 优先级相同时按权重分流，单台随便填 |
| 端口 Port | 34567 | 服务实际监听的端口 |
| 目标 Target | relay.example.com. | 真正的主机名 |

## 三个坑

### 坑一：目标只能填主机名，不能填 IP

这是最容易错的地方。SRV 记录的 `Target` 字段**必须是一个能解析的主机名**，不能直接写 IP 地址。

也就是说，你不能这样写：

```text
_minecraft._tcp.play.example.com.  SRV  0 5 34567 203.0.113.45
```

正确做法是给那台机器一个主机名，让它有 A 记录，然后 SRV 指向那个主机名。如果用的是内网穿透，隧道服务商给你的节点域名本身就是个主机名，直接拿来用就行。

### 坑二：玩家输入时不能带端口

这条听起来奇怪，但很关键。

SRV 记录**只在玩家没有指定端口时才会被查询**。一旦玩家写成了这样：

```text
play.example.com:34567
```

客户端就会认为"你已经告诉我端口了"，直接跳过 SRV 查询，去连那个端口。

所以配置好之后，发给朋友的地址必须是不带端口的版本。加了端口，记录就白配了。

### 坑三：基岩版基本不支持

Java 版和基岩版在这件事上不一样。基岩版理论上也支持 SRV（用 `_udp` 协议），但**大量基岩版客户端会忽略它**，尤其是手机和主机版。

所以如果你同时开着基岩版互通，手机玩家还是得手动填地址和端口，没有优雅的解决办法。

## 各家 DNS 面板的差异

SRV 记录字段多，不同服务商的面板长得完全不一样，这也是很多人卡住的地方。

**合并式**面板只有一个「值」输入框，整条记录按 `优先级 权重 端口 目标` 的顺序写成一整行：

```text
0 5 34567 relay.example.com
```

**拆分式**面板会把每个字段做成独立的输入框，需要分别填服务和协议：

| 字段 | 值 |
|---|---|
| 服务 Service | `_minecraft` |
| 协议 Protocol | `tcp` |
| 姓名 Name | `play` |
| 值 Value | `relay.example.com` |
| 优先级 | `0` |
| 权重 | `5` |
| 端口 | `34567` |

注意拆分式面板里，「姓名」只填子域名（`play`），不要再写一遍 `_minecraft._tcp`，否则会变成 `_minecraft._tcp._minecraft._tcp.play`。

> 我用的一家服务商，协议框填 `_tcp` 会被拒绝，报"protocol 无效"，去掉下划线填 `tcp` 才通过。所以如果保存时报错，先怀疑下划线，别怀疑自己填错了。

## 怎么验证配对了没有

不要配完就直接发给朋友，先自己查一下。Windows 上用 `nslookup`：

```powershell
nslookup -type=srv _minecraft._tcp.play.example.com
```

macOS 或 Linux 上用 `dig`：

```bash
dig SRV _minecraft._tcp.play.example.com +short
```

期望看到的就是你刚才填的那四个值。如果查不到，先等几分钟 —— DNS 需要时间传播，各家面板的 TTL 不同。实在着急可以换个公共 DNS 直接查，绕过本机缓存：

```bash
dig SRV _minecraft._tcp.play.example.com @223.5.5.5
```

有个小情况值得一提：本机运营商 DNS 的缓存经常比别人慢。我配好之后，阿里、腾讯、谷歌、Cloudflare 四个公共 DNS 都查到了，只有本机运营商 DNS 还返回"记录不存在"。这种情况不用管，等缓存过期就好。

## 一个附带的好处

SRV 记录有个常被误解的地方：**它不能隐藏你的真实 IP**。任何人都能查 DNS 看到目标，再解析一次就拿到 IP 了。它不是 DDoS 防护。

它只解决一件事：让地址变短、变好记、变好发。这件事很小，但对一个要频繁发给朋友的地址来说，值得花十分钟配上。
